# DeepSeekによる証明生成とLeanによる検証

証明の作成・修正は `deepseek-v4-1-flash-1017` が担当し、ローカル側は
入力の準備、Leanの実行、エラーの返送、検証済み成果の保存を行う。
この手順に切り替えた後のモジュールは、証明本文を人手で修正せずに生成する。
以前の `RecoveredDivisor.lean` と `NormalizedCancellation.lean` の作成経緯は
`ADDITIONAL_FORMALIZATION.md` の説明のままである。

## 参照した公開リポジトリ

コードの移植ではなく、以下の検証・改善手順を参照した。

- [OpenAI lean-gym README](https://github.com/openai/lean-gym/blob/1585ac4d2e56a1ceb72243ce859645b9d0069d34/README.md)：
  証明状態とエラーを返し、完成した証明の型が最初のゴールと一致することを確認する。
  証明穴を含む項を拒否する。このリポジトリはLean 3.39.1用であり、
  今回のLean 4.35.0環境にそのまま導入していない。Apache-2.0。
- [Anthropic evaluator-optimizer](https://github.com/anthropics/claude-cookbooks/blob/ce8b2629efe8b24048b127b4c79af1e9cbab93d4/patterns/agents/evaluator_optimizer.ipynb)：
  生成→評価→フィードバック→再生成のループと、生成とは別の評価呼び出し。
  今回は評価の中心をLLMの自己採点ではなくLeanコンパイラに置く。MIT。
- [OpenAI Evals README](https://github.com/openai/evals/blob/8eac7a7de5215c907fbddc30efdaf316913eccdd/README.md)：
  評価条件を先に固定し、結果を記録して比較できるようにする。

OpenAI/Anthropicの非公開研究手法を再現したという意味ではない。
外部リポジトリの実装コードを今回のランナーへコピーしていない。

## 今回の実装

`deepseek_proof_loop.py` に定理文を固定する。DeepSeekから受け取れるのは、
その定理名をキーとしたJSON形式の証明本文だけである。
モデルが仮定や結論を書き換えて簡単な定理へ置き換えることはできない。

1. 明示した文脈ファイル、固定した定理文、公開参考資料をAPIへ送る。
2. 返った証明本文を固定した定理文に組み込む。
3. 宣言の注入、証明穴、独自公理、ネイティブ決定手続きなどを拒否する。
4. 固定バージョンのLeanで実際にコンパイルする。
5. 失敗や警告があれば、実出力を同じモデルへ返して全証明本文を再生成させる。
6. Leanで成功した後も別のDeepSeek呼び出しで定理の意味と説明の対応を点検する。
7. 両方通過した成果だけをソースに採用し、各試行のハッシュ・終了コード・使用量を残す。

複数ゴールをまとめた生成では同じ誤りが繰り返されたため、
`deepseek_goal_worker.py` では一度に1定理へ分割する。成功した証明本文は固定し、
次の定理の失敗で書き換えない。失敗が続くと別のDeepSeek評価呼び出しで
数学的な誤推論・反例・ライブラリAPIの問題を診断し、その結果を生成側へ返す。
途中まで成功した証明は `accepted_proofs.json` から読み込み、Leanで再確認して再開できる。

モデルによる意味の点検は外部研究者の査読や、独立した別モデルによる監査ではない。
数学的な形式検証の根拠は、固定された定理文とLeanの成功記録である。

不明な定理名のエラーが出た場合、固定mathlib内の定義・補題をローカル検索して
実際の宣言を生成側へ返す。座標変換の検証では、失敗した最後のタクティクスが
作った残差と、その直前の実ゴールを区別し、診断用に取得した状態を返した。
これらは前提検索・証明状態取得の考え方を取り入れた実装である。

追加でDeepSeek-Prover-V2、DeepMind、Meta、Numina、LeanDojo等の11リポジトリを
共有した記録は [参考資料一覧](../AI_RESEARCH_REFERENCES.md) にある。

APIキーは `MISTRAL_API_KEY` の既存バインディングを使い、保存・表示しない。
試行の原文やプロンプトは非公開研究を含み得るため、この環境内の指定run-dirへ保存する。
GitHubへの送信・公開はこのランナーの機能に含まれない。

## 対象と限界

- `square`：正規化平方合同式から、非平方の場合の付値の下限と素数冪の全回復へ進む。
- `crt`：局所三次合同式の素数冪ごとの分岐と、有限個の合同条件の存在・一意性、平方値のCRT集約。
- `cf_core`：近似定数3/2を使う連分数の整数係数表示と係数上限。全曲線の排除とは別の証明義務。

CRTの候補クラス数の上限、平方根の持ち上げ、解析的高さ上限、
全有限領域の完全性、元の四変数方程式全体の非存在証明は別の証明義務である。
上記モジュールが通っても、それらがすべて完了したとは扱わない。

`geometry_job.json` はモデル案を点検して固定した幾何学用の定義・定理文で、
`--job-config` から読み込む。`GeometricReduction.lean` の9個の証明本文はDeepSeekが生成・修正した。
API呼び出し時にはリポジトリ内の委任スキル、研究状態、参考資料要約を都度読み込む。
公開参考資料のダウンロード用作業ディレクトリがなくても、コミットした手順要約を利用できる。
