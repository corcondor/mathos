# v20：補分岐の既約分子を、全ての不足約数に対して J≥33 へ絞る

2026-11-07 JST。記述証明と完全な整数計算の証明書。
新しい Lean 形式化・DeepSeek API 呼び出し・外部査読を主張しない。

## 1. 結論と対象

元の式は添字を二乗する

\[
\binom{\binom ij}{\binom{k}{\ell}}
=\binom{i^2}{j^2}+\binom{k^2}{\ell^2}.
\]

\(\ell=1,j=i-3\) の枝で \(n=i\)、\(A=\binom n3\)、
\(r=\min(k,A-k)\) とする。このノートは **補分岐 \(k=A-r\)** を扱う。

\[
N=n^2+2,\qquad T=(r-1)^2-9n^2-6n-10>0,
\]
\[
G=\gcd(N,T),\qquad w=N/G,\qquad J=T/G.
\]

今回、

\[
\boxed{J\ge33\qquad(k=A-r)}
\tag{1}
\]

を証明した。\(n\) や不足約数 \(\delta\) に実験的な上限を置いていない。
新しい対数評価で、仮定 \(J\le32\) からまず \(w\le383\) を導き、
その有限範囲を約数として完全に復元する。

小分岐の既存 \(J\ge17\) と、この補分岐の結論は別である。
両分岐全体・四変数方程式全体の解決ではなく、\(J\) の上限は依然としてない。

## 2. 使用する条件

元式の解について、次が既に証明されている。

\[
n\ge104,\quad3n<r<10n/3,\quad r-3n>3\sqrt n,
\]
\[
w\ge65,\qquad\gcd(w,J)=1,\qquad J\not\equiv2\pmod4.
\tag{2}
\]

\(w\ge65\) は `v18_neighbor_cofactor_height.md` 第7節、
2進条件は `v19_canonical_J_elimination.md` 第2節による。
canonical な \(G\) を使っているため既約性を適用できる。

同じ v18 ノートの第2節より、

\[
g=\gcd(n,3),\quad d=\gcd(n-1,6),\quad
c_0=9w+2J,\quad c_1=24w+3J
\]

に対して

\[
\boxed{\frac ng\mid c_0^3,\qquad\frac{n-1}{d}\mid c_1^3.}
\tag{3}
\]

特に、右辺が正なので \(n\le3(9w+2J)^3\)。
新しい入力は `v20_logarithmic_gap.md` の一般証明

\[
\boxed{w<\frac7{16}J\log n\qquad(n\ge1024)}
\tag{4}
\]

である。この評価は元の二項係数等式の \(\binom Ar>B\) を実際に使う。
後述の有限計算から推測している条件ではない。

## 3. J≤32 なら、w は 65〜383 の間だけでよい

以後 \(1\le J\le32\) と仮定する。\(t=r-3n>3\sqrt n\) から

\[
T=6n(t-2)+(t-1)^2-10
>18n^{3/2}-3n-6\sqrt n-9>17n^{3/2}
\]

が \(n\ge104\) で成り立つ。最後は \(\sqrt n>10\) による。
また \(N<(5001/5000)n^2\) である。従って

\[
w=J\frac NT<\frac{5001}{85000}J\sqrt n.
\tag{5}
\]

もし \(n<1024\) なら \(\sqrt n<32\) であり、
\(5001\cdot32<2\cdot85000\) より \(w<2J\le64\) となって (2) に反する。
よって \(n\ge1024\) で、(4) が使える。

第一の約数条件と (4) を合わせ、さらに \(J\le32\) を使うと

\[
w<\frac7{16}J\log\{3(9w+2J)^3\}
\le14\log\{3(9w+64)^3\}.
\tag{6}
\]

一方、\(f(w)=w-14\log\{3(9w+64)^3\}\) は \(w\ge384\) で増加する。

\[
f'(w)=1-\frac{378}{9w+64}
\ge1-\frac{378}{9\cdot384}=\frac{57}{64}>0.
\]

端点の厳密な比較は

\[
3(9\cdot384+64)^3=130842624000<2^{37},
\]
\[
f(384)>384-14\cdot37\cdot\frac7{10}=\frac{107}{5}>0.
\]

ここで \(\log2<7/10\) は数値近似ではない。正の指数級数を4次まで足すと
\(\sum_{a=0}^4(7/10)^a/a!=482921/240000>2\) となる。
従って \(w\ge384\) の全域が (6) と矛盾する。
得られた完全な有限範囲は

\[
\boxed{1\le J\le32,\quad65\le w\le383,\quad
\gcd(w,J)=1,\quad J\not\equiv2\pmod4.}
\tag{7}
\]

## 4. n の走査を、二つの約数条件へ置き換える

固定した (7) の各 \((J,w)\) について、\(c_0,c_1\) を定める。
第一条件 (3) により、可能な \(n\) は必ず

\[
e\mid c_0^3,\quad g\in\{1,3\},\quad n=ge,
\quad n\ge104,\quad\gcd(n,3)=g
\tag{8}
\]

のリストに現れる。正の約数を**すべて**生成するので、
\(n\) の大きさに任意の打切り上限を置く必要がない。
続いて、実際の \(d=\gcd(n-1,6)\) に対して
\((n-1)/d\mid c_1^3\) を検査し、さらに
\(w\mid n^2+2\)、\(G=(n^2+2)/w\) を要求する。

最後に必須の平方条件

\[
\boxed{(r-1)^2=9n^2+6n+10+JG=(9w+J)G+6n-8}
\tag{9}
\]

を整数平方根で検査する。\(\gcd(w,J)=1\) なので、もしここで \(r\) が
復元できれば \(\gcd(N,T)=G\) も成立する。

## 5. 完全な有限証明書

| 段階 | 件数 |
|---|---:|
| (7) の全係数族 \((J,w)\) | 5,323 |
| 全約数と \(g=1,3\) の組 | 608,102 |
| \(n\ge104\)、実際の \(g\) が一致 | 429,917 |
| 第二の約数条件も満たす | 862 |
| \(w\mid n^2+2\) も満たす | 5 |
| (9) が平方 | **0** |

最後の5件を省略せず示す。\(S\) は (9) の右辺、\(a\) はその整数平方根。

| J | w | n | G | S | a | 短い合同反証 |
|---:|---:|---:|---:|---:|---:|---|
| 1 | 118 | 1,216 | 12,531 | 13,327,741 | 3,650 | S≡5 mod8 |
| 8 | 89 | 129 | 187 | 152,049 | 389 | S≡3 mod9 |
| 8 | 121 | 2,197 | 39,891 | 43,773,601 | 6,616 | S≡12 mod17 |
| 9 | 278 | 784 | 2,211 | 5,556,517 | 2,357 | S≡2 mod5 |
| 29 | 102 | 976 | 9,339 | 8,849,881 | 2,974 | S≡5 mod7 |

全てで \(a^2<S<(a+1)^2\) を直接確認した。右欄の剰余もそれぞれ平方非剰余であり、
整数平方根とは別の短い点検にもなる。従って整数 \(r\) が存在せず、
仮定 \(J\le32\) は矛盾する。これが (1) の証明である。

有限計算では必要な \(n\ge1024\) をあえて追加せず、\(n\ge104\) の
広い約数集合を排除した。表に小さい \(n\) が含まれていても、
証明に必要な範囲を落としているわけではない。
二項係数の Lucas 反証を新たに計算したとは主張しない。
今回は、その前の整数平方条件ですべて消えている。

## 6. 独立検査と再現

生成器 `v20_complement_J_cover.py` は試し割りで \(c_0\) を因数分解し、
指数の直積から \(c_0^3\) の全約数を生成する。
全5,323族、正規化された候補集合のハッシュ、全862点、最後の5件を
`v20_complement_J_certificate.json.gz` に保存した。

別実装 `v20_complement_J_verify.py` は生成器を import しない。
最小素因数のふるい・再帰的約数生成・集合での \(n\) の正規化を使い、
全候補を作り直す。(9) は別の右辺から計算し、平方根も二分探索で求める。
係数の全域、各族の候補数、全862点、5件すべての隣接平方数の不等式が一致した。
標準 Python ライブラリだけで、両方とも PASS。

同じ研究ディレクトリに資料を置けば、次で再現できる。

```sh
python v20_complement_J_cover.py
python v20_complement_J_verify.py
```

別配置の場合、生成器には `--research-dir` と `--gap-note`、
検査器には `--gap-note` を指定する。
新しい対数評価・旧入力ノートのハッシュを証明書に記録し、
検査器は実際の対数評価ノートの一致も確認する。

この検証は完全な有限算術証明書と記述証明の組合せである。
一般の対数評価や過去の約数移送を Lean で形式化したという意味ではなく、
内部の独立点検を外部研究者の査読とは呼ばない。
